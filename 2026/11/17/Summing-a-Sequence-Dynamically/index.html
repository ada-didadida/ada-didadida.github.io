动态求和一个序列

发表于2026-11-17|更新于2026-11-17|C#翻译
|总字数:2529|阅读时长:11 分钟|浏览量:

在书的一份早期草稿里，演示如何只在托管代码中使用动态类型的那一节，大部分篇幅都花在了"动态求和一个序列"这个任务上。后来语言的行为发生了变化，我不得不重写那一节，把例子改得更宽泛一些，但动态求和这个任务本身仍然足够有趣，值得记录下来。本文会讨论其中一部分可行的做法。为了让没有这本书的读者也能看懂，我会从零讲起，而不是接着书里的内容往下写。（这也意味着，如果书里有哪个地方你没看明白，这个页面或许能提供一种不同的解释，让你一下子"开窍"。）

我们想要达成什么？

LINQ to Objects 里的 Enumerable.Sum 有一大堆重载——可即便如此，它也不是什么都能处理。比如我们可能想对 TimeSpan 值求和——或者短整型，或者无符号整数——但这些场景框架里都没有提供。我们来看看能不能做得更好。如果能写出一个静态类型的泛型方案，用类似"该类型必须有一个 public static T operator +(T, T) 运算符"这样的约束来表达，那该多好，可惜没有这个选项。那就改用动态类型吧。

选择签名：先试试 IEnumerable<dynamic>

我们首先要决定的是 DynamicSum 方法该用什么签名。一种选择是用 IEnumerable<dynamic> 作参数，返回值也是 dynamic。你可能觉得这挺容易的，但它有两个明显的问题：

  • 我们最常想求和的元素类型是值类型——而泛型变体不适用于值类型，所以我们没法从（比如说）IEnumerable<int> 转换成 IEnumerable<dynamic>。我们得写成 values.Select(x => (dynamic) x).Sum() 这种不太好看的东西，或者从一开始就用 dynamic 构建一个集合。
  • 没有一个天然的"零"值。如果序列里至少有一个值，那还好办；但如果没有呢，该返回什么？整数 0？double 的 0.0？decimal 的 0.0m？还是一个 null 引用？当然，我们也可以把零值作为另一个参数传进来……但这也挺烦人的。

处理可空类型

Enumerable.Sum 中那些接受可空类型序列（比如 IEnumerable<int?>）的重载，行为和其他重载不太一样。如果我们把序列里的每一个项都加起来，结果会是 null——因为在 C# 可空类型的提升运算符规则下，把任何东西加到一个 null 值上都会得到 null。

所以那些常规的 LINQ to Objects 方法会直接跳过所有 null 值。尽管这些方法的返回类型是可空的，但返回的值永远不是 null，即使输入序列为空、或者只包含 null 值也一样。
